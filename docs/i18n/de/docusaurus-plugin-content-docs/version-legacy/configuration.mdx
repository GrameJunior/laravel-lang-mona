## Veröffentlichen {/* #publish */}

Bei Bedarf kannst du die Konfigurationsdatei mit dem folgenden Befehl veröffentlichen.

```bash
php artisan vendor:publish --tag="localization"
```

So sieht die veröffentlichte Datei `config/localization.php` aus.

## Inline {/* #inline */}

Die Option `inline` legt fest, welcher Dateityp beim Aktualisieren der Sprachdateien verwendet wird.

- Bei `true` werden Inline-Dateien verwendet.
- Bei `false` werden Standarddateien verwendet.

Das folgende Beispiel zeigt den Unterschied.

```text
The :attribute must be accepted. // Standardübersetzung
This field must be accepted. // Inline-Übersetzung
```

Diese Option steht in der Datei `config/localization.php` zur Verfügung.

```php
return [
    'inline' => (bool) env('LOCALIZATION_INLINE', env('LANG_PUBLISHER_INLINE')),
];
```

## Ausrichtung {/* #alignment */}

Die Option `align` legt fest, wie die Werte beim Verarbeiten von Sprachdateien zueinander ausgerichtet werden.

Beim Aktualisieren verschwinden alle Kommentare aus den Zieldateien, weil [var\_export](<https://www.php.net/manual/en/function.var-export.php>) keine Kommentare verarbeiten kann.

Beispiel für die ursprüngliche Datei

```php
declare(strict_types=1);

return [
    /*
    |--------------------------------------------------------------------------
    | Meldungen zur Authentifizierung
    |--------------------------------------------------------------------------
    |
    | Die folgenden Texte werden für verschiedene Meldungen während
    | der Authentifizierung verwendet. Du kannst sie an die Anforderungen
    | deiner Anwendung anpassen.
    |
    */
    'failed'   => 'These credentials do not match our records 123456.',
    'throttle' => 'Too many login attempts. Please try again in :seconds seconds.',
    'foo'      => 'bar',
];
```

Die aktualisierte Datei sieht so aus.

```php
declare(strict_types=1);

return [
    'failed'   => 'These credentials do not match our records 123456.',
    'throttle' => 'Too many login attempts. Please try again in :seconds seconds.',
    'foo'      => 'bar',
];
```

Beispiel für die Datei `validation.php`

<details>
<summary>Inhalt anzeigen</summary>

```php
declare(strict_types=1);

return [
    /*
    |--------------------------------------------------------------------------
    | Validierungsmeldungen
    |--------------------------------------------------------------------------
    |
    | Die folgenden Texte enthalten die Standardfehlermeldungen der
    | Validierungsklasse. Manche Regeln haben mehrere Varianten, etwa
    | die Regeln zur Größe. Du kannst die Meldungen hier anpassen.
    |
    */
    'accepted'   => 'The :attribute must be accepted.',
    'active_url' => 'The :attribute is not a valid URL.',

    // weitere Regeln

    'uuid' => 'The :attribute must be a valid UUID.',
    /*
    |--------------------------------------------------------------------------
    | Benutzerdefinierte Validierungsmeldungen
    |--------------------------------------------------------------------------
    |
    | Hier kannst du eigene Validierungsmeldungen für Attribute definieren.
    | Verwende als Namen das Muster "attribute.rule", um einer Regel für
    | ein bestimmtes Attribut eine eigene Meldung zuzuweisen.
    |
    */
    'custom' => [
        'name' => [
            'required' => 'Custom message 1',
            'string'   => 'Custom message 2',
        ],
    ],
    /*
    |--------------------------------------------------------------------------
    | Benutzerdefinierte Validierungsattribute
    |--------------------------------------------------------------------------
    |
    | Die folgenden Texte ersetzen Attribut-Platzhalter durch verständliche
    | Bezeichnungen wie "E-Mail Address" für "email". Damit lassen sich
    | die Meldungen verständlicher formulieren.
    |
    */
    'attributes' => [
        'name' => 'Foo',
        'bar'  => 'Bar',
        'baz'  => 'Baz',
    ],
];
```

</details>

So sieht die Datei nach der Aktualisierung aus.

```php
declare(strict_types=1);

return [
    'accepted'   => 'The :attribute must be accepted.',
    'active_url' => 'The :attribute is not a valid URL.',
    'uuid'       => 'The :attribute must be a valid UUID.',
    'custom'     => [
        'name' => [
            'required' => 'Custom message 1',
            'string'   => 'Custom message 2',
        ],
    ],
    'attributes' => [
        'name' => 'Foo',
        'bar'  => 'Bar',
        'baz'  => 'Baz',
    ],
];
```

Diese Option steht in der Datei `config/localization.php` zur Verfügung.

```php
return [
    'align' => (bool) env('LOCALIZATION_ALIGN', env('LANG_PUBLISHER_ALIGN', true)),
];
```

## Aliasse {/* #aliases */}

Wenn du andere Codes verwenden möchtest, etwa `de-DE` statt `de` oder `de-CH` statt `de_CH`, definiere `aliases` in der [Konfigurationsdatei](<./configuration.mdx#aliases>).

Die Befehle zum Hinzufügen, Aktualisieren und Entfernen verwenden anschließend automatisch die Aliasse aus der Konfigurationsdatei `config/localization.php`.

```php
declare(strict_types=1);

use LaravelLang\LocaleList\Locale;

return [
    'aliases' => [
        Locale::German->value            => 'de-DE',
        Locale::GermanAustria->value     => 'de-AT',
        Locale::GermanSwitzerland->value => 'de-CH',
    ],
];
```

Existiert die Datei `config/localization.php` bereits, kannst du den Alias-Schlüssel ergänzen und die gewünschten `aliases` als Array angeben.

Danach kannst du beispielsweise neue Locales hinzufügen, indem du entweder den Hauptcode oder seinen Alias angibst.

```bash
php artisan lang:add de de_CH
```

Installierte Locales verwenden die angegebenen Aliasse als Verzeichnisnamen für PHP-Übersetzungen und als Dateinamen für JSON-Übersetzungen.

```text
lang
de-CH
de-DE
```

Diese Option steht in der Datei `config/localization.php` zur Verfügung.

```php
return [
    'aliases' => [
        // \LaravelLang\LocaleList\Locale::German->value => 'de-DE',
        // \LaravelLang\LocaleList\Locale::GermanSwitzerland->value => 'de-CH',
    ],
];
```

## Intelligente Zeichensetzung {/* #smart_punctuation */}

Beim Aktualisieren von Übersetzungen kannst du auch die intelligente Umwandlung von ASCII-Anführungszeichen, Bindestrichen und Auslassungspunkten in Unicode-Zeichen aktivieren.

Beispiel

```json
{
    "Some": "\"It's super-configurable... you can even use additional extensions to expand its capabilities -- just like this one!\""
}
```

Das Ergebnis sind die folgenden Dateien.

```json
{
    "Some": "“It’s super-configurable… you can even use additional extensions to expand its capabilities – just like this one!”"
}
```

Diese Option steht in der Datei `config/localization.php` zur Verfügung.

## Routes {/* #routes */}

Wenn du das Paket für das [Routing](<./packages-routes.mdx> "Routen einfach und schnell lokalisieren") verwendest, kannst du die vorgegebenen Schlüsselnamen überschreiben.

Diese Option ist in der Datei `config/localization.php` aktiviert.

```php
use LaravelLang\Config\Constants\RouteName;

return [
    'routes' => [
        'names' => [
            'parameter' => RouteName::Parameter,
            'header'    => RouteName::Header,
            'cookie'    => RouteName::Cookie,
            'session'   => RouteName::Session,
            'column'    => RouteName::Column,
        ],

        'name_prefix' => env('LOCALIZATION_NAME_PREFIX', 'localized.'),
        'redirect_default' => (bool) env('LOCALIZATION_REDIRECT_DEFAULT', false),
        'hide_default' => (bool) env('LOCALIZATION_HIDE_DEFAULT', false),

        'group' => [
            'middlewares' => [
                'default' => [
                    LaravelLang\Routes\Middlewares\LocalizationByCookie::class,
                    LaravelLang\Routes\Middlewares\LocalizationByHeader::class,
                    LaravelLang\Routes\Middlewares\LocalizationBySession::class,
                    LaravelLang\Routes\Middlewares\LocalizationByModel::class,
                ],
                'prefix' => [
                    LaravelLang\Routes\Middlewares\LocalizationByParameterPrefix::class,
                    LaravelLang\Routes\Middlewares\LocalizationByCookie::class,
                    LaravelLang\Routes\Middlewares\LocalizationByHeader::class,
                    LaravelLang\Routes\Middlewares\LocalizationBySession::class,
                    LaravelLang\Routes\Middlewares\LocalizationByModel::class,
                ],
            ],
        ],
    ],
];
```

## Models {/* #models */}

Mit dem Paket [Models](<./packages-models.mdx> "Modelle einfach und schnell lokalisieren") kannst du Standardwerte für die Parameter festlegen.

Diese Einstellung steht in der Datei `config/localization.php` zur Verfügung.

```php
return [
    'models' => [
        'suffix' => 'Translation',
        'filter' => [
            'enabled' => (bool) env('LOCALIZATION_FILTER_ENABLED', true),
        ],
        'helpers' => env('VENDOR_PATH', base_path('vendor/_laravel_lang')),
    ],
];
```

Der Parameter `suffix` legt das Suffix der Modelle fest, zu denen das Übersetzungs-Repository gehört.

Beispiel

```text
App\Models\Post::class
App\Models\PostTranslation::class
```
